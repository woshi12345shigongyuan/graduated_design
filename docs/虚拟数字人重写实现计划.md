# 虚拟数字人重写实现计划

## 目标
在不改变整体项目架构的前提下，摒弃现有卡通风格数字人，重写为**更逼真、生动、完全免费**的真人化虚拟形象。

## 现状简述
- **前端**：`Avatar.vue` 为 SVG 卡通形象（厨师帽、简单几何形），口型为随机开合，无真实唇形同步。
- **后端**：使用 edge-tts 生成语音，返回 `audio_url`，无口型数据。
- **交互**：ChatPanel 通过 `avatarStatus`（idle/thinking/speaking）与 `isSpeaking` 控制状态。

## 技术要求对照

| 要求 | 实现方案 |
|------|----------|
| 视觉真实感 | 使用真人半身/头像底图（CC0/免版权）+ 光影与皮肤质感通过 CSS 与图层叠加增强 |
| 唇形同步 | 方案 A：后端提供 viseme 关键帧（Rhubarb Lip Sync），前端按音频 currentTime 插值驱动口型；方案 B：前端 Web Audio AnalyserNode 根据振幅驱动嘴部开合（零后端改动、流畅） |
| 微表情 | 眼神随机缓慢移动、眉毛按情绪微调、头部轻微晃动、自然眨眼间隔 |
| 情感表达 | 保留 emotion 状态，映射到眉毛弧度、嘴角曲线，可扩展简单手势区域 |
| 响应与流畅 | 口型用 requestAnimationFrame 与音频 currentTime 同步，保证 60fps；状态切换即时 |
| 完全免费 | 仅使用开源/免费：edge-tts、Rhubarb（可选）、免版权素材、Web API |
| 真人化 | 弃用卡通 SVG，改用真人照片 + 口型/微表情动画层 |

## 架构不变点
- Vue 3 前端、FastAPI 后端、现有 `/api/chat/send` 与 TTS 流程不变。
- 仅扩展接口（如返回 `viseme_data` 或 `viseme_url`），前端兼容“无 viseme 时用振幅驱动”。

## 实现步骤

### 阶段一：前端真人化与口型（不依赖后端口型数据）
1. **素材**：在 `public/` 或 `frontend/src/assets/` 放置一张免版权真人讲解员风格图片（或占位图），作为数字人底图。
2. **新 Avatar 组件**：
   - 底层：真人半身/头像图片，适当圆角与阴影。
   - 口型层：独立 div/canvas 或 SVG，仅绘制嘴部区域；口型由“开合度 + 嘴角”两个维度控制，便于与振幅或 viseme 映射。
   - 微表情层：眼神（瞳孔或高光位置）、眉毛、头部使用 CSS transform + JS 更新，数据来自内部状态（情绪 + 随机种子）。
3. **口型驱动（首版）**：使用 Web Audio API：
   - 播放语音时，用 `AudioContext` + `AnalyserNode` 分析当前播放的音频振幅。
   - 在 `requestAnimationFrame` 中根据振幅计算“嘴部开合度”，平滑插值后更新口型层，实现与声音同步、过渡自然。
4. **微表情逻辑**：
   - 眨眼：随机间隔（如 2–5 秒）触发一次闭合动画。
   - 眼神：每 3–5 秒在合理范围内随机移动目标点，平滑过渡。
   - 头部：idle/speaking 时轻微左右/上下正弦漂移；thinking 时略加强。
   - 眉毛：由 `emotion`（neutral/happy/confused/sorry）映射到预设弧度或位移。
5. **情感**：保留并沿用 `emotion`，驱动眉毛与嘴角曲线，使表情与语境一致。

### 阶段二：后端唇形数据（可选增强）
6. **Viseme 服务**：
   - 在 TTS 生成音频后，调用 Rhubarb Lip Sync（或等价开源工具）：输入为音频文件 + 文本，输出为时间–口型关键帧（JSON）。
   - 若使用 Rhubarb：需将 edge-tts 输出的 mp3 转为 wav（如 pydub/ffmpeg），再调用 Rhubarb 命令行；中文可采用 phonetic recognizer（语言无关）。
   - 在 `ChatResponse` 中增加可选字段 `viseme_data`（或 `viseme_url`），仅当生成成功时返回。
7. **前端**：当存在 `viseme_data` 时，口型驱动改为“根据 `audio.currentTime` 在关键帧间插值”；否则继续使用振幅驱动，保证兼容与流畅。

### 阶段三：打磨与性能
8. **流畅度**：口型与微表情统一在单一 `requestAnimationFrame` 循环中更新；在非 speaking 时降低更新频率或仅更新眨眼/眼神。
9. **响应速度**：保持现有“用户发送 → 后端 RAG+TTS → 返回 answer + audio_url”流程；前端收到即开始播放并驱动数字人，无额外阻塞。
10. **资源**：真人图片可配置或可替换；所有依赖与素材均需为开源/免费授权，不接入商业付费 API。

## 文件变更清单（预期）
- **前端**：重写 `frontend/src/components/Avatar.vue`；可能新增 `frontend/src/composables/useLipSync.js`（或类似）封装音频分析与口型/viseme 逻辑；`ChatPanel.vue` / `App.vue` 仅做必要的 props/事件传递（如传入 `audioElement` 或 `currentAudioUrl` + `visemeData`）。
- **后端**：可选新增 `api/services/lip_sync_service.py`，在 `api/routes/chat.py` 中 TTS 成功后调用并返回 `viseme_data`；`ChatResponse` 增加可选字段。
- **资源**：新增真人底图资源路径（如 `public/avatar-host.png`），并在文档中说明可替换为其他免版权素材。

## 验收要点
- 视觉为真人形象，无卡通元素。
- 说话时口型与语音在时间上同步，过渡自然、无机械卡顿。
- 具备眨眼、眼神移动、眉毛与头部微动。
- 表情能随情绪（emotion）变化。
- 全程使用开源/免费技术与素材，无商业 API。
- 交互响应及时，动画流畅（目标 60fps）。

## 实现状态（当前）

### 实时免费渲染方案（当前实现）

- **实时渲染**：数字人由 **Canvas 2D 每帧重绘** 实现真正“实时渲染”。单一 `requestAnimationFrame` 循环（约 60fps）内完成：清空画布 → 应用头部微动变换 → 绘制底图（真人照片或程序化皮肤）→ 绘制眼睛/眉毛/口型/眨眼遮罩。无预渲染视频、无服务端渲染，完全在浏览器内免费实时绘制。
- **前端结构**：
  - `useAvatarRenderer.js`：接收 `canvasRef` 与口型/情绪/眨眼/头部偏移等响应式数据，每帧调用 `drawFrame()`，绘制程序化皮肤（径向渐变）或 `avatar-host.png` 底图，再叠加眼睛、眉毛、口型、眼睑。
  - `Avatar.vue`：提供 Canvas、可选底图 `<img>`、`useLipSync` 唇形、眨眼/头部漂移定时器，并在 `onMounted` 后 `nextTick(startRenderer)` 启动渲染循环。
- **唇形/微表情/情感**：与前述方案一致——`useLipSync` 基于 Web Audio 振幅驱动 `mouthOpenness`；情绪驱动眉毛弧度与口型曲线；眨眼与头部漂移由定时器更新；所有数据在每帧被读入并绘制，保证流畅一致。
- **真人化**：若存在 `public/avatar-host.png` 且加载成功，底图使用该真人照片；否则使用程序化绘制的肤色与五官（径向渐变皮肤 + 眼睛/嘴/眉），无卡通元素。
- **阶段二**：未实现。可后续在 TTS 后接入 Rhubarb Lip Sync 等生成 `viseme_data`，前端在存在 viseme 时按时间插值驱动口型。
- **素材**：真人底图可选，放置为 `frontend/public/avatar-host.png`，参见 `frontend/public/avatar-host.txt`。
